# 足彩

## 版本

V0.2

## 目标

固定玩法：

- 7场比赛
- 每场结果空间 = 主胜 / 平 / 客胜
- 共 `3^7 = 2187` 个互斥精确赛果组合
- 固定预算 = ¥16
- 2元/注
- 最终选择 8 注 7串1

**第一目标：最大化8注的联合覆盖概率。**

赔率不是第一排序条件。不得为了满足某个固定高赔率门槛，主动放弃概率更高的组合。

---

## 核心原则

### 1. 先概率，后收益

先计算全部2187个组合的模型概率，再选择8个组合。

若8注互斥，则联合覆盖概率：

```
P_cover = Σ P(combo_i), i ∈ selected_8
```

选择目标：

```
maximize P_cover
subject to |selected_8| = 8
```

随后再做收益检查。

禁止：

```
先筛 odds >= 60
再在剩余组合里找概率最高的8注
```

因为这会系统性牺牲全中率。

### 2. 固定预算

- 总预算：¥16
- 注数：8
- 单注：¥2
- 不自动加码
- 不因“玄学强信号”扩大预算

### 3. 赔率60不是每注死门槛

不得要求8注全部满足赔率≥60。

可记录以下收益指标：

- 每注赔率
- 8注概率加权平均赔率
- 最低潜在回报
- 最高潜在回报
- 核心票与补充分支票的收益分布

收益约束属于第二阶段，不得覆盖第一阶段的概率目标。

### 4. 市场概率不是绝对真值

当前模型尚未证明存在稳定、可复制、足以击败市场的广义定价优势。

因此：

- 概率估计必须保守；
- 不得把微小模型差异包装成确定优势；
- 不得把赔率更高自动解释为“更有价值”；
- 若无稳定增量证据，优先使用去水市场概率或经过验证的概率融合。

# 输入

每场至少需要：

- match_id
- league
- kickoff_time
- home_team
- away_team
- odds_H
- odds_D
- odds_A

推荐额外输入：

- 交易所概率
- 亚洲盘口
- 开盘 / 临场变化
- 伤停 / 首发
- xG / 近期表现
- 赛程与休息天数

所有特征必须是赛前可获得信息。

禁止未来数据泄漏。

---

# STEP 01｜概率生成

对每场生成：

```
P(H), P(D), P(A)
```

若使用欧赔，先去水：

```
qH = 1 / odds_H
qD = 1 / odds_D
qA = 1 / odds_A

P(H) = qH / (qH + qD + qA)
P(D) = qD / (qH + qD + qA)
P(A) = qA / (qH + qD + qA)
```

若存在经样本外验证的模型，可与市场概率融合。

不得仅因模型输出和市场不同，就自动相信模型。

---

# STEP 02｜确定7场

先从当天候选比赛中确定最终7场。

7场筛选目标：

- 数据完整
- 开赛前信息足够
- 概率分布可解释
- 避免明显数据异常
- 尽量避免7场全部高度依赖同一类热门结构

此步骤输出：

```
MATCH_1 ... MATCH_7
```

每场保留完整 H/D/A 概率。

---

# STEP 03｜枚举2187组合

生成：

```
3^7 = 2187
```

个精确组合。

例如：

```
H-H-A-D-H-A-H
H-H-A-D-H-A-D
...
```

每个组合概率：

```
P(combo) = Π P_i(result_i)
```

基础实现默认条件独立。

若未来引入相关性模型，必须单独验证，不能事后调整。

---

# STEP 04｜剔除无效组合

这里只允许剔除**明确无效**组合，例如：

- 数据缺失
- 赔率异常或明显错误
- 结果对应赔率无法下注
- 规则不允许的市场
- 已封盘 / 已开赛
- 存在数据源冲突且无法解决

不得仅因为赔率“不够高”而提前删除概率较高的组合。

---

# STEP 05｜选择8注

在可下注组合中，优先选择联合覆盖概率最大的8个互斥精确组合。

因为所有2187组合本身互斥，基础版本等价于：

```
按 P(combo) 从高到低排序
取 Top 8
```

输出：

- Rank
- 7场精确结果路径
- P(combo)
- decimal_odds
- stake = ¥2
- potential_return

并计算：

```
P_cover = Σ Top8 P(combo)
```

这是整套系统最重要的命中率指标。

---

# STEP 06｜收益检查

选出Top 8以后，再检查收益。

检查：

- 每注赔率
- 最低赔率
- 最高赔率
- 概率加权平均赔率
- ¥16总投入下的各路径毛回报
- 是否出现“为了覆盖概率而全部压成极低回报”的情况

若收益过低：

1. 不得直接把全部低赔率组合删掉；
2. 应比较替换某一注后：
   - 联合覆盖概率损失多少；
   - 收益改善多少；
3. 只接受可解释的概率—收益交换。

最终必须同时报告：

```
P_cover_before_return_constraint
P_cover_after_return_constraint
coverage_cost
```

其中：

```
coverage_cost =
P_cover_before_return_constraint
- P_cover_after_return_constraint
```

---

# STEP 07｜集中风险节点

8注确定后，统计每场每个结果在8注中的出现次数。

例如：

```
Match 3:
H = 7/8
D = 1/8
A = 0/8
```

定义“集中风险节点”：

- 某一结果出现在大多数注中；
- 一旦该结果判断错误，会同时杀死大量组合；
- 且该结果的市场概率没有高到可以忽略风险。

优先找2–3场。

输出：

```
CONCENTRATION_RISK_1
CONCENTRATION_RISK_2
CONCENTRATION_RISK_3
```

排序依据首先是“错误会杀死多少注”，其次才是主观不确定性。

# STEP 08｜六爻终审（保留）

六爻只用于2–3个集中风险节点。

**六爻不负责挑7场，不负责枚举2187，不负责决定预算。**

当前状态：

```
EXPERIMENTAL / FORWARD-TEST ONLY
```

在验证通过前，六爻只记录信号，不直接修改正式8注。

## 起卦

采用用户赛前提供6个数字的数字代摇法。

冻结规则：

- 6个数字自下而上对应初爻→上爻
- 奇数 = 阳
- 偶数 = 阴
- 3 / 6 / 9 = 动爻

赛后不得改变起卦规则。

## 六爻分析层

按固定传统框架记录：

- 本卦
- 变卦
- 世应
- 用神
- 月建
- 日辰
- 旺衰
- 动爻
- 变爻
- 空亡
- 月破 / 日破
- 冲合
- 进退
- 伏神 / 飞神（如适用）

## 六爻输出

只允许三类标签：

```
SUPPORT
RISK
STRONG_RISK
```

含义：

- SUPPORT：未发现明显反向风险
- RISK：原集中方向存在风险
- STRONG_RISK：反向风险明显

禁止输出“必中”“必输”。

---

# STEP 09｜六爻前瞻验证

六爻必须先证明增量，再获得修改8注的权限。

每次赛前封存：

- match_id
- cutoff_time
- 6个起卦数字
- 本卦 / 变卦
- 六爻标签
- 当时算法概率
- 该结果在8注中占几注
- 正式8注原始版本
- 最终赛果

禁止赛后改标签。

阶段目标：

- 先积累 50 个终审样本
- 推荐达到 100 个后再判断是否有稳定价值

核心评估：

```
P(favorite hits | SUPPORT)
P(favorite hits | RISK)
P(favorite hits | STRONG_RISK)
```

以及：

```
7/7 hit rate without Liuyao
7/7 hit rate with hypothetical Liuyao adjustment
```

必须使用前瞻样本或严格留出样本。

---

# STEP 10｜六爻升级条件

只有当六爻在足够样本中稳定显示增量时，才能进入概率修正层。

未来可能形式：

```
P'(H,D,A) = f(P(H,D,A), Liuyao_signal)
```

然后重新：

```
2187枚举
→ Top 8联合覆盖优化
→ 收益检查
```

在通过验证前：

```
P' = P
```

六爻不得改变正式下注组合。

# NO BET

允许输出：

```
NO BET
```

条件包括：

- 数据源异常
- 关键赔率不可用
- 7场无法形成可靠概率
- 8注收益结构严重失真
- 实际下注市场与模型赔率不一致到无法解释
- 开赛时间 / 封盘状态导致执行不可行

NO BET不能因为六爻“不吉”而触发。

# 回测规则

任何策略修改必须比较：

```
BASELINE
vs
NEW_RULE
```

至少记录：

- eligible dates
- 7/7 hits
- hit rate
- 8注联合覆盖概率
- 实际赔率
- ROI（若数据完整）
- 最大连续未中
- 最大回撤（若资金曲线可计算）

任何从训练数据发现的规则，必须在未来赛季或严格留出样本验证。

禁止：

- 同一数据发现规则又宣布验证成功
- 赛后改六爻解释
- 只展示成功案例
- 因小样本高命中就升级生产规则
