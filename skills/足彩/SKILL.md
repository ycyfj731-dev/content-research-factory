# 足彩

## 版本与适用范围

V0.3。本文是规则规范，不代表计算程序已经实现、模型已经训练或回测已经通过。仅有文档时，不得虚构程序、预测档案、历史命中率或收益结果。

固定玩法：7场、每场主胜H／平D／客胜A、8条不同的完整7串1路径、每注¥2、总预算¥16。不自动加码，不将两个方案合并成16注，不沿用固定4单3双的结构限制。

第一目标是最大化8注覆盖真实完整赛果的概率。默认正式方案为 COVER；RETURN-CONSTRAINED 是独立的可选方案，须预先配置明确收益底线及采用模式。每周六／周日按用户提供的赛事范围处理，不通过事后挑选“好日子”美化命中率。

正式撤回“组合层已经解决”。准确表述为：

> 给定固定7场和可信联合概率后，无约束Top8路径选择问题已解决，但整个7串1系统未解决。

选场、时点、概率估计、可执行性、收益约束和系统验证仍需分别证明。

## 01｜冻结整票出票时间与候选池

对最终所选7场集合 M，冻结：

```text
T_ticket(M) = min(kickoff_time_i for i in M) - 30分钟
```

所有用于整票决策的赔率、伤停、首发、xG、交易所概率及其他特征，其信息可用时间戳必须 <= T_ticket。不能只满足“各自比赛开赛前”。

- 时间统一保存为带时区的时间；同时保存数据来源、源发布时间、采集时间、可用时间和快照标识。
- feature_available_at 按信息真实可被系统获得的时间确定；生产采集使用不早于发布时间和采集时间的时间。仅有比赛发生时间不足以证明数据可用。
- 历史快照必须能证明当时可用；赛后下载的历史文件不能仅凭旧比赛日期当成当时快照。缺乏证据的数据标记为不可用于无泄漏回测。
- 特征、校准器、融合权重及模型训练标签也须在决策时点可用；滚动统计不能包括尚未结束或尚未发布的数据。
- 同一整票中，晚场在 T_ticket 之后发布的首发、赔率或新闻全部禁止使用。不得事后补齐再声称赛前预测。

### 处理“选场决定时点”的循环

在每个可决策时点 t，以该时点已知的赛程和信息形成候选池 C_t。该时点可搜索的集合定义为：

```text
A_t = {M subset C_t: |M|=7 and min(kickoff_time_i for i in M)=t+30分钟}
```

因此，同一次联合搜索中所有集合使用同一个 t，且最终 T_ticket=t。较晚集合所需的未来快照不能提前参与当前选择。

跨时点是否等待必须是一项事前冻结、只读取当时及过去信息的执行策略。默认在当天用户赛事范围内第一个存在合法7场、8条可下注路径的决策时点进行搜索；后续时点只能在此前不可执行且尚未出票时处理。RETURN-CONSTRAINED 在该共同决策时点无可行解则报告 INFEASIBLE，不得为寻找更好收益而临时推迟。用户另行指定的等待策略须单独封存和验证。

若用户指定固定7场，直接按其最早开赛时间计算 T_ticket，不另行换场。当前已错过 T_ticket 时，只可说明历史时点重建条件或不可执行；不能把较晚信息回填成准时出票。

出票前按当时已知赛程复核公式与封盘状态；已出票后发生改期、取消等，保留原始快照并按真实结算规则记录，不改写过去的 T_ticket。

## 02｜输入与可执行性

每场至少保存：

- match_id、league、home_team、away_team、kickoff_time、赛程版本；
- market_id、结果定义、结算口径（包括是否让球、是否仅常规时间）；
- forecast_source、forecast_odds_H/D/A 及各自快照时间；
- execution_source、execution_odds_H/D/A、报价时间、可下注状态；
- 所用特征及其 available_at、数据来源和版本；
- p_forecast_H/D/A、模型版本及生成时间。

概率市场与执行市场必须对应同一赛果定义。普通胜平负概率不能直接套用到让球胜平负。概率来源与执行赔率可以相同，但须明确标识。

按在 t 时可确认的可购买状态、数据完整性、市场规则及事前固定的数据质量规则形成 C_t。只排除明确无效数据或不可执行路径；不得凭主观“热门太集中”预筛7场，不得在 COVER 中按高赔率门槛预删路径。

执行报价须在 t 有效；只有实际规则允许时才用各腿报价乘积计算组合赔率，存在舍入、限额或其他结算差异时按执行平台规则记录。后续真实成交／结算另记，不用于回改选票。

## 03｜预测概率、市场基线与融合

明确分离：

```text
p_forecast_i(r) = 对比赛结果的预测概率
execution_odds_i(r) = 实际可购买结果的十进制赔率
```

每场三分类预测须有限、非负且总和为1。比例去水市场基线为：

```text
q_ir = 1 / forecast_odds_ir
Z_i = sum_r q_ir
p_market_ir = q_ir / Z_i
```

这是市场概率基线，不是独立价值信号，不代表真实概率已被验证。不得把与市场的微小差异自动解释为优势。

在独立乘积模型下，若预测与执行使用同一组赔率、同一快照且组合赔率为乘积，则：

```text
P_M(s) * O_execution(s) = 1 / product_i Z_i
```

同一7场集合内所有路径的模型期望毛回报比例相同，不能用这个循环宣称发现了相对价值。不同来源也不自动产生优势；价值判断仍须依赖经验证的预测、真实执行价格及成本。

候选模型可包括球队实力、进球模型、xG或ML，但仅在时间外证明增量后参与融合。融合权重在内层训练／验证中确定，保持有效概率分布；允许市场模型权重100%、其他模型权重0，不为模型数量强行分权。共享数据的多个模型不视为独立证据。

### robust score 的边界

```text
robust_score = p_forecast - lambda * sigma
```

此量只称 robust score，不称预测概率、校准概率或真实胜率，不代入正式路径概率乘积与 P_cover。sigma 的定义、估计方法及 lambda 必须预先冻结，稳健决策作为独立实验评估。

区间更窄不自动提高平均命中率；若64%与61%是可信的预测均值，不能只因前者不确定性较大就声称后者更容易命中。双选概率的不确定性须考虑两项概率的协方差。

## 04｜联合概率与固定7场的数学结论

对每个 M 枚举全部 3^7=2187 条完整赛果路径 s。基线采用给定共同信息集 I_t 后的条件独立模型：

```text
P_M(s | I_t) = product_i p_forecast_i(s_i | I_t)
```

独立性是待验证假设。只有相关性模型在留出数据上证明稳定增量后，才可用经过验证、非负且归一化的联合分布替代乘积。不得因“同一天、同联赛、全是热门”主观添加相关性折扣；共同模型误差与赛果依赖须区分。

**固定同一7场时，不同完整赛果路径互斥，所以：**

```text
P_cover(M,S) = sum_{s in S} P_M(s), |S|=8
```

概率相加不依赖比赛独立，乘积计算才依赖独立假设。固定 M 且没有额外收益约束时，选概率最高8条可执行路径即为最优。

路径必须去重。不同7场集合的票不一定互斥，禁止将它们的覆盖率直接相加。取消、走盘或特殊结算改变事件定义时须按真实规则另行处理，不能继续机械套用精确赛果互斥假设。排除不可购买路径后，不得对剩余概率重新归一化。

## 05｜COVER：7场与8注联合优化

在共同 t 和 C_t 上，对全部合法集合 M in A_t：

```text
V_t(M) = M的可下注完整路径集合
S_C(M) = V_t(M)中概率最高的8条不同路径
F_t(M) = sum_{s in S_C(M)} P_M(s | I_t)
M_C = argmax_{M in A_t} F_t(M)
S_C = S_C(M_C)
```

若用户固定7场，只计算该集合。若某集合不足8条合法路径，则该集合不可行。

不得先按热门概率、主观信心、单选排名或“分散热门”确定7场后宣称全局最优。对每个集合枚举2187条，只解决了内部路径排序，不代替集合搜索。

可使用穷举或有最优性保证的等价算法；若只能用启发式／有限搜索，必须报告搜索范围、停止条件、已知上界或最优性缺口（未知则如实写未知），并称“当前找到的最佳方案”，不得称全局最优。

概率并列时采用预先固定的 match_id 排序和 H、D、A 路径字典序规则，不以赛后结果破同分。

COVER 不设赔率60门槛，不在看到收益后换票；收益仅展示。

## 06｜RETURN-CONSTRAINED：预设收益底线下联合优化

此模式不是 COVER 的事后人工修补。搜索前冻结 constraint_type、数值阈值、成本／税费口径、结算方法及正式采用模式，写入 experiment_id。未配置收益底线时输出 NOT_CONFIGURED，不发明默认阈值，COVER 仍正常运行。

使用与 COVER 相同的 t、C_t、A_t、p_forecast 和可执行路径空间，同时优化7场与8条路径：

```text
(M_R,S_R) = argmax P_cover(M,S)
subject to M in A_t, S subset V_t(M), |S|=8,
           predeclared_return_constraint(M,S)=true
```

允许的明确约束类型包括以下之一；若组合使用，须提前完整列明：

- MIN_PATH_GROSS：每条入选路径中奖毛回报 R_s 均 >= B。标准每注¥2且赔率含本金时 R_s=2*O_execution(s)；例如 B=16 表示中奖时毛回报覆盖整票投入，不代表期望盈利。此例不是默认阈值。
- CONDITIONAL_MEAN_GROSS：sum_s P_M(s)*R_s / P_cover >= B，要求 P_cover>0。它约束“已中奖时的平均毛回报”，不保证每条路径回本。
- EXPECTED_NET：sum_s P_M(s)*R_s - 16 - expected_costs >= E_min。须明确费用是否已包含，禁止重复扣除；非负仅是模型估计，不是盈利保证。

按结算口径调整上述公式，禁止将三种约束混称“收益好”。单路径底线可先筛路径再取Top8；组合级平均／期望约束不能假设简单排序或贪心替换一定最优。

无可行解则报告 INFEASIBLE，不悄悄降低阈值、不临时换模式、不增加预算。若事前已指定可回退 COVER，则按冻结策略执行并记录。

同时报告：

```text
P_cover_COVER
P_cover_RETURN_CONSTRAINED
coverage_cost = P_cover_COVER - P_cover_RETURN_CONSTRAINED
```

两方案可选不同7场，但必须同一时点、候选池与预测。精确求解时 coverage_cost>=0；近似搜索出现负值应标记搜索误差，不能宣称加约束提高理论最优覆盖率。无可行解时差值记不适用。

## 07｜分支覆盖质量与敏感性

正式8注确定后，对每场 i、结果 r：

```text
W_ir = sum_{s in S: s_i=r} P_M(s)
N_ir = count(s in S where s_i=r)
```

W_ir 是该分支承载的无条件覆盖概率质量；P_cover>0 时 W_ir/P_cover 为覆盖质量占比。每场 sum_r W_ir=P_cover。它不是该结果的边际预测概率，也不是“该结果失败后仍能中奖”的条件概率。

以 W_ir、对应 p_forecast 及概率扰动敏感性识别2–3个主要审查节点。扰动范围、重算方式须预先指定且保持有效概率分布。N_ir／“会杀死几注”只作辅助描述，不作为首要风险排序。

集中可能是覆盖率最优的自然结果，不自动减分、不强行分散，也不凭敏感性分析人工改正式票。

## 08｜六爻隔离前瞻实验

状态：EXPERIMENTAL / FORWARD-TEST ONLY。只对按冻结规则选出的2–3个审查节点记录，不参与选7场、p_forecast、预算、正式8注、等待决策或 NO BET。

- 用户提供6个数字，自下而上对应初爻至上爻；
- 奇数阳、偶数阴，3／6／9为动爻；
- 按固定框架记录本卦、变卦、世应、用神、月建日辰、旺衰、动变爻、空破、冲合、进退及适用的伏神／飞神；
- 标签仅 SUPPORT、RISK、STRONG_RISK，不输出必中／必输。

冻结数字输入范围、规则版本、解释到标签的映射及分析时间；禁止重起卦挑信号或赛后改标签。没有有效数字则记 MISSING，不补造。

只比较 SUPPORT／RISK 原始命中率不能证明增量：必须控制原始预测概率，并按冻结方案处理赛事／时点等必要混杂因素。用前瞻或未参与开发的留出数据比较“概率基线”与“概率基线+信号”的增量，再评估事前冻结的假想调整对整票的影响。

50／100个样本只是检查点，不是自动升级门槛。样本量、检验指标、重复检验控制和成功条件事前确定；同日多个节点不能当成独立日期。

只有控制原始概率后证明稳定增量，才有资格研究概率修正，仍须独立验证并进行新版本决策。V0.3 始终 P'=P，Production impact=NONE。

## 09｜验证协议与实验记录

### 时间外测试

1. 外层按时间滚动或使用真正未参与开发的未来赛季／日期；不得随机混合未来与过去。
2. 所有特征选择、模型参数、去水方法、融合权重、校准器、收益阈值及等待策略，只在外层测试之前的内层训练／验证数据上确定。
3. 校准使用与基础模型拟合适当隔离的样本或按时间生成的样本外预测；融合也不能用基模型训练内预测冒充样本外表现。最终外层测试不得参与拟合或调参。
4. 根据外层结果改规则后，该段数据成为开发信息，不能继续称全新独立验证。最终判断使用新的未触碰数据。

### 公平比较与统计单位

- 在相同日期、T_ticket、候选池快照、市场口径、预算和执行规则下配对比较 BASELINE 与 NEW_RULE；选场策略允许选不同7场。
- 若策略改变出票时间或等待规则，另列端到端策略实验，完整披露时间与信息差异，不能归因于概率模型改善。
- 记录所有计划日期、可行日期、未出票原因和覆盖率，不只展示成功日或有票日。
- 同一整票8条路径是互斥选项，不是8个独立统计样本。命中指标按票／决策日统计；同日多票、节点或重复实验考虑聚类／时间依赖。
- 区间与重采样按日期或合适的时间区块进行；报告配对差异及不确定性，不仅展示点估计。
- 固定4单3双、筛日策略和V0.3属于不同系统，历史命中率不能直接移植。

### 评估指标

同时记录：

- 单场：三分类 Log Loss、Brier、H/D/A 校准曲线、样本量及重要分层；Brier下降不能单独证明校准改善。
- 整票：实际覆盖指示、预测 P_cover、按预测分档的票级校准、命中率及区间、最大连续未中。
- 决策：候选数量、搜索状态、正式模式、收益约束、coverage_cost、可执行性。
- 收益：真实成交和结算数据完整时才报告ROI、回撤和回报分布；预测期望与实际收益分开。

每次规则变更保存 experiment_id、父版本、提交版本、研究假设、创建时间、数据／快照标识、内外层日期、时点与候选池规则、参数搜索范围、选中规则、所有尝试摘要、指标、失败结果及决定。重复试验和未通过模型都保留，不只保存胜出者。

## 10｜输出、封存与不可执行状态

每次运行输出：

- 所选7场：match_id、开赛时间、p_forecast_H/D/A、预测来源与时间、执行报价与时间；
- 8注：完整路径、P_M(s)、执行赔率、¥2投入、路径中奖回报；
